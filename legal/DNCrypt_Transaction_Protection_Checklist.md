# Before signing either document

- Insert an immutable commit/archive hash and exact file list. Never sign an asset definition such as 'DNCrypt and all related technology'.

- Keep PNCS, GREMLIN, NOEMA, CIEL, PhaseNav, PNV-State-Memory, PNFS and PNH5 in the Excluded/Retained schedule by name.

- Keep DNCRYPT_CHECKPOINT_WIRE_V0_1 and successor interoperability schemas in the retained/shared category.

- For a sale, do not delete clauses 7 and 8 (licence-back + non-assert/patent covenant) without specialist advice.

- Do not transfer the GitHub account, email account, API tokens, private keys, NOEMA/CIEL runtime, or unrelated repositories.

- Do not transfer source code before cleared payment and any required export-control/NSI clearance.

- Have a solicitor review contributor/contractor ownership, third-party licences and title before giving an IP ownership warranty.

- Keep evidence wording exact: internal/controlled evidence is not independent cryptanalysis or certification.

- If the buyer asks for exclusivity, make it field-limited and preserve Retained Project rights; avoid a broad non-compete.

- Require every onward buyer/assignee to take the IP subject to the retained licence-back and non-assert covenant.

- Use secure channels for bank details, source-code delivery and credentials. Do not put secrets in the signed public PDF.

- Check VAT/tax treatment with an accountant and export classification with ECJU/export-control counsel if the buyer is overseas.

# Preferred deal order

**1.** NDA / limited due diligence.

**2.** Non-exclusive or field-limited commercial licence / paid pilot.

**3.** Independent cryptanalysis and buyer technical diligence.

**4.** Only then negotiate an exclusive licence or asset sale if the price justifies it.

**5.** If an asset sale occurs, sell the exact DNCrypt snapshot - not the surrounding ecosystem.
